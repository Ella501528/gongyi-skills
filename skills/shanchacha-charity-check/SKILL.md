# 善查查 · 公益机构尽职调查（方法框架版）

> 这一版公开的是**方法与判断框架**：一家公益机构，从公开披露资料到一份能被人复核的调查报告，这件事分几个阶段、每个阶段在解决什么问题、报告里哪些内容必须交代清楚、结论凭什么站得住。
>
> 读完你能判断：这套路子适不适合你要做的核查，值不值得投入。
>
> 需要真正动手执行时（自动取数、工商穿透、成稿交付），走完整版按次调用。

---

## 一、这个流程解决什么问题

把一家公益机构，从「一堆审计报告 PDF」变成「一份机构调查报告 + 全套可复核底稿」。

三条主线，也是报告的三块重点：

1. **资金链网状追踪** —— 从捐赠入口到最终收款方的全额映射，含关联方与关联交易
2. **灰色合规地带的标记、定级与分析** —— 规则化提示 + 政策依据 + 整改建议
3. **实质性社会成效** —— 区分产出 / 结果 / 影响，写清成效边界与已被证伪的指控

**核心方法**：审计报告给「名字」，工商穿透给「身份」，招采公告给「价格」——三者叠加才是完整资金链。

审计报告**永远不会**写深度关联关系和关联交易（关联方章节可能整章缺失），所以外部工商穿透与关键人交叉不是可选项，是这个流程真正的价值所在。

**没有工商账号也能做**：退回公开披露口径，报告照样出，但必须在报告的资金链章节如实标注取数边界。

## 二、什么时候该用，什么时候不该用

**该用：**

- 「给某基金会做一份机构调查」
- 「查一下某机构的资金链 / 关联方 / 关联交易」
- 「把某份报告的资金链部分补一下」
- 「做一下理事和供应商的人脉交叉」

**不该用（以下请求不要启动这套流程）：**

| 请求 | 为什么不该用 | 该走哪 |
|---|---|---|
| 「写一篇公益行业观察 / 公众号文章」 | 这是内容创作，不是机构取证 | 写作类能力 |
| 「给我一份项目立项书 / 预算表」 | 立项合规是另一条线，与尽调取证无关 | 立项合规类能力 |
| 「查一下某公司的工商信息」 | 只说企业、没有机构尽调意图，不必起整条流水线 | 通用检索 |
| 「这家基金会值不值得捐」 | 本流程只出**证据与边界**，不给捐赠建议 | 如实说明边界后按需出尽调 |
| 「把上次那份报告再发我一份」 | 只是取件，不需要跑流程 | 直接定位交付包文件 |

> 拿不准时，先问一句：是要出一份尽调报告，还是只是查个信息。

## 三、整体分三个阶段

| 阶段 | 在解决什么问题 | 产出什么 |
|---|---|---|
| **一、资料准备** | 把公开披露的原始资料**完整**拿到手，并转成可检索、可复核的文本 | 原始资料归档 + 逐份文本 + 取证清单 |
| **二、取证** | 把报告里的「名字」变成「身份」：交易对手、关联方、关键人查透 | 工商底稿 + 关键人交叉结果 |
| **三、成稿交付** | 写成报告、渲染交付件、做完整性自证 | 报告（HTML + PDF）+ Excel 底稿 + 交付说明 |

三个阶段的顺序不能颠倒，原因在第五节。

**资料准备阶段要解决的三个具体问题：**

1. **哪里取** —— 公开披露渠道（年检年报、审计报告、章程、理事监事名单、关联交易、招采公告等）是主来源
2. **拿得全** —— 列表页往往分页，附件可能挂在子页，扫描件需要另做文字还原；任何一环静默失败都会丢信息
3. **转成可查的** —— 扫描件必须先做文字还原（OCR）；没有还原之前，不要凭印象写那几年的数字

**取证阶段要解决的三个具体问题：**

1. **主体是谁** —— 交易对手的股东结构、实际控制、变更沿革
2. **人有没有闭环** —— 理事、监事、关键经办人在外部的任职与持股，与供应商名单交叉比对
3. **边界在哪** —— 没有账号时，哪些结论只能依赖公开披露，必须在报告里写清楚

**成稿交付阶段要解决的三个具体问题：**

1. **报告怎么组织** —— 按固定骨架写，每章回答一个明确问题
2. **交付件怎么齐** —— HTML 阅读版 + PDF + Excel 底稿，外加一份交付说明
3. **怎么证明没漏** —— 出报告前跑一遍完整性自证（第五节）

## 四、报告要覆盖的内容

产出是一份**七章机构调查报告**，交付形态为 HTML 阅读版 + PDF + Excel 底稿。

三块重点内容必须落到实处：

| 重点 | 必须交代清楚的事 |
|---|---|
| **资金链** | 从捐赠入口到最终收款方的全额映射；关联方与关联交易的识别过程；哪些是股权层关联、哪些只是商业关系 |
| **灰色合规地带** | 按规则化提示逐项标记，给出政策依据，区分「立案 / 被质疑」与「已认定违规」 |
| **实质性社会成效** | 区分产出、结果、影响三层，写明成效边界，以及哪些指控已被证伪 |

**几条贯穿全报告的写作纪律：**

- 每个数字都要能溯源。转引、倒推、估算的必须标注来源；查不到的写「未查到」
- 风险标记是**提示不是结论**，措辞用「建议 / 需关注 / 高亮预警」
- 穿透之后要回头改定性。名义上的关联闭环可能在股权层被证伪；公司名含知名集团但实为自然人持股，要标为名称巧合
- 交出去的每一版都必须是可直接交付的成品，正文里不出现版本痕迹与过程性说明
- 只补充或更新指定的章节，其余章节保持不动

## 五、为什么这份结论可信：三层自证

公开资料的取数链条长——分页、按需加载、弹窗附件、扫描件、格式混杂，**任何一环静默失败都会丢信息**。而「丢了没丢」如果靠人眼比对，换个人来用必然翻车。

所以这三件事被做成**机器自证**，出报告前逐条核完：

| 层 | 保证什么 | 怎么自证 |
|---|---|---|
| ① 采集完整性 | 公开披露的资料**下载齐** | 逐表对账「页面声明条数 vs 实抓条数」；子标签内容指纹；附件存在性与文件头校验；截图查重 |
| ② 解析覆盖 | **任何格式**都能提取到有效信息 | 认文件头不认扩展名；文本层弱的自动采用 OCR 结果；不支持的格式**明示**而非静默丢弃 |
| ③ 分析覆盖 | 报告**不遗漏必查项** | 固定必查清单逐项对照，未出现的提示确认：确无此项，还是漏了 |

**这三层都不依赖任何账号** —— 采集与解析针对公开数据，分析覆盖是文本比对。也就是说，换个使用者拿到这套流程，跑一遍自证就能发现「哪里没下全、哪里没提取到、哪里没分析」，不必相信任何人的口头保证。

**这一节也是三个阶段顺序不能颠倒的原因**：资金链是报告的主体，穿透结论会反转定性。如果先出报告再补穿透，主体章节和结论都要重写。所以取证必须排在动笔之前。

## 六、能力边界（先说清楚，避免误用）

| 边界 | 说明 |
|---|---|
| **扫描件必须做文字还原** | 审计报告中有相当比例是纯图片扫描件。还原没跑完之前，不要写那些年份的数字 |
| **工商数据有边界** | 未登录只能拿到基础工商信息；股东穿透、关键人查询等深度字段需要相应权限 |
| **账号是使用者自己的** | 每个使用者登录自己的账号，凭证只落在本机；不代登录、不碰密码、不上传凭证。**没有任何账号是必需的** |
| **绝不假装做过** | 没有账号时不要在报告里假装做过工商穿透，如实写「未做穿透 / 未查到」 |
| **不替代判断** | 脚本只负责取数与搬运，报告质量取决于写作与判断。**没有任何一条命令能自动吐出完整的七章报告** |
| **使用条款红线** | 只用于使用者自身的合规尽调，控制访问频率，不做数据转售或公开分发 |
