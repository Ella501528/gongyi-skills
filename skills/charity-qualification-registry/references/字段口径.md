# 字段口径

入库与查询时的字段含义、取值规则与处理口径。

---

## 一、`org` 机构主表

| 字段 | 含义 | 口径说明 |
|---|---|---|
| `org_id` | 机构主键 | 慈善中国内部 ID（链接参数 `aaee0101`）；非慈善中国来源的机构以 `ext:<名称>` 占位 |
| `uscc` | 统一社会信用代码 | 18 位；**前两位可推断组织类别** |
| `name` | 机构名称 | 来源站点的规范全称，已剥离状态后缀 |
| `org_type` | 组织类别 | 社会团体／民办非企业单位／基金会；按 `uscc` 前两位推断，见下 |
| `establish_date` | 成立时间 | 统一为 `YYYY-MM-DD` |
| `registrar` | 登记管理机关 | 对应「注册部门」，如「北京市民政局」 |
| `prov` / `city` / `dist` | 所属省／市／区县 | 预留，部分来源可解析 |
| `charity_date` | 慈善组织认定登记日期 | 仅慈善中国提供 |
| `legal_person` | 法定代表人 | 仅慈善中国详情页提供 |
| `address` | 组织住所 | 仅慈善中国详情页提供 |
| `business_scope` | 业务范围 | 仅慈善中国详情页提供 |
| `status` | 组织状态 | 正常／注销／撤销 |
| `credit_status` | 信用状况 | 正常／活动异常名录／严重违法失信名单 |
| `supervisor_unit` | 业务主管单位 | **慈善中国不提供**，字段预留 |
| `first_seen` / `last_seen` | 首次／最近入库时间 | 用于判断记录新鲜度 |

### 组织类别推断规则

统一社会信用代码第 1–2 位为登记管理部门与机构类别代码：

| 前两位 | 组织类别 |
|---|---|
| 51 | 社会团体 |
| 52 | 民办非企业单位（社会服务机构） |
| 53 | 基金会 |

该规则使抓取列表时无需额外请求即可补全组织类别。校验：9,174 + 5,055 + 2,524 = 16,753，与慈善中国公示总数一致。

## 二、`qual` 资质表

一机构一资质一行，主键为 `(org_id, qual_type)`。

| 字段 | 含义 | 口径说明 |
|---|---|---|
| `org_id` | 机构主键 | 外键指向 `org` |
| `qual_type` | 资质类型 | 见下方取值表 |
| `has_flag` | 是否具有 | 1 有／0 无；负向名单置 1 表示「在名单内」 |
| `grade` | 等级 | 评估等级类资质使用（如 3A／4A／5A） |
| `valid_from` / `valid_to` | 有效期起止 | 年份或日期，视来源而定 |
| `source` | 来源 | 发布主体，公告类含文号 |
| `source_url` | 来源链接 | 用于回溯核验 |
| `evidence` | 原始凭证 | 公告批次标题、筛选条件等原文摘录 |
| `fetched_at` | 抓取时间 | 判断数据新鲜度 |

### 资质类型取值

| `qual_type` | 对应名录 |
|---|---|
| `R1 慈善组织登记认定` | 慈善组织名录 |
| `R2 公开募捐资格` | 公开募捐资格 |
| `R3 公益性捐赠税前扣除资格` | 捐赠税前扣除 |
| `R4 非营利组织免税资格` | 免税资格 |
| `R5 社会组织评估等级` | 评估等级 |
| `R6 信用状况` | 活动异常名录／严重违法失信名单 |
| `R7 慈善信托备案` | 慈善信托 |
| `R8 互联网公开募捐服务平台` | 募捐平台 |

### `has_flag` 语义

对**正向名录**（R1–R5、R7、R8）：`1` 表示该机构在名单内。

对 **R6 信用状况**：`1` 表示该机构**在异常名录或严重违法失信名单内**——即存在负面信用记录。查询时须注意这一语义差异，`evidence` 字段记录了具体是「活动异常名录」还是「严重违法失信名单」。

## 三、`changelog` 变更日志

| `change_type` | 触发条件 |
|---|---|
| `新增` | 该机构此前无此资质记录，本次首次入库 |
| `值变更` | 同一资质的值发生变化（如评估等级由 3A 升为 4A） |
| `失效` | 正向名录中，本次抓取未再出现 |
| `退出名单` | 公告类名单中，本次公告未再列入 |
| `移出名单` | R6 信用状况中，本次抓取未再出现（即已移出异常名录） |

R6 使用「移出名单」而非「失效」，因为该记录表示风险状态解除，语义不同于资质丧失。

---

## 四、合并抓取时的比对规则

同一资质类型若由**多个筛选条件分次抓取**（如 R6 由 `xyzk=2` 与 `xyzk=3` 两次抓取合并），必须把各次的命中集合合并后**只执行一次**「未出现即失效」比对。

若各次抓取各自比对，先抓批次会被后抓批次误判为失效。实现上通过 `fetch(..., seen_out=shared_set, mark_expired=False)` 共享集合，最后统一调用比对。

---

## 五、日期与文本规范化

| 情形 | 处理 |
|---|---|
| 英文月份（`Aug 27, 2026`） | 转 `2026-08-27` |
| 全角空格、`&nbsp;` | 统一去空白 |
| 机构名尾随标点 | 去除 `，。；、` 等尾随符号 |
| 状态后缀 | 从名称列剥离后单列 `status` 字段 |
| 名单条目编号 | 支持 `1.` `1、` `1．` 三种分隔符 |

---

## 六、名称匹配

公告类名单以机构全称列出，入库时按 `name` 精确匹配库内机构：

- 匹配成功 → 直接写 `qual`
- 匹配失败 → 以 `ext:<名称>` 建立仅含名称的机构记录，便于后续补全

影响：机构改名时，历史记录可能落在旧名下；同名机构可能误合并。需要严格判定时应回到源站按统一社会信用代码确认。
