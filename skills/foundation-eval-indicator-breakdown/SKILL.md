# 指标拆解与资料清单生成

把一份官方评估指标表，变成**每个岗位能照着干活**的逐项资料清单。

## 一、适用场景与前置条件

**适用**：等级评估、专项评估、年检自查自评等一切"指标表驱动"的迎评准备。

**前置条件（缺一不可）**：

| 前置 | 说明 | 缺失时的处理 |
|---|---|---|
| 指标文件 | 官方发布的评估指标表（xlsx 为佳） | 向用户索取；无表则先做版本核验与框架梳理 |
| 机构信息 | 机构全称、简称、参评年度 | 用于命名交付物与说明页 |
| 年度区间 | 材料覆盖年度（一般近三年） | 默认"参评年度前推三年" |
| 指标版本 | 版本号与发布日期 | **必做**先核对是否为当年最新版（核验动作见 §八） |

> 若指标表是"标准模板"（未填内容），本技能负责**从零撰写**；若指标表已填部分内容（规定依据、考查方式、资料清单列已有值），本技能负责**重构增强**——两者流程相同，仅"撰写强度"不同。请先判断属于哪一种，并在说明页写明，避免用户误以为重复劳动。

## 二、核心概念

| 概念 | 定义 |
|---|---|
| **末级考查要点** | 指标树的最末端条目（编号形如 `1.1.1.1`），是评分与资料准备的**唯一粒度** |
| **类型** | `客观`＝纯材料审查；`主观`＝材料＋执行痕迹与效果（案例、成效、数据，现场询问概率高）；`客观+主观`＝两者兼有 |
| **简繁档位** | 说明文字的详略档（`详`/`标准`/`简`），由 分值 × 类型 决定，**只影响撰写深度，不影响得分口径** |
| **规定依据** | 该项对应的法律法规/部门规章/规范性文件，尽量到**条款号或文号**；无正式文号的标【实操指引，非法定依据】 |
| **考查方式** | 评估专家如何查证该项（材料审阅／现场询问／案例讲解／系统核验／第三方佐证／穿行测试） |
| **电子版资料清单** | 文件级的材料名（名称＋年度范围＋格式），可直接作为归档文件名 |
| **资料说明（why）** | 向一线负责人解释"为什么要这份资料、评估时怎么被使用、要注意什么" |

## 三、脚本与流水线

脚本位于 `scripts/`，用托管 Python 运行（见 §六 环境说明）。

```bash
# 1) 抽取：指标表 → source_extract.json（展开合并单元格、清洗、求和校验）
python scripts/extract_source.py --src "<指标表.xlsx>" --sheet "<工作表名>" \
       --org "<机构简称>" --out "<工作目录>"

# 2) 增强元数据：source_extract.json → enriched_meta.json（档位/负责人/文件夹/待核验标记）
python scripts/tier.py --work "<工作目录>" [--owner-map "<自定义映射.json>"]

# 3) 切分批次：enriched_meta.json → batches/input_*.json（按一级指标切分，供分批撰写）
python scripts/split_batches.py --work "<工作目录>"
```

三步产出的目录结构：

```
<工作目录>/
  source_extract.json      # 原始抽取结果（含 lawtext/basis/method/matlist 等源列）
  enriched_meta.json       # 加档位、负责人、文件夹路径、needs_verify、code_mismatch
  batches/
    input_1_<一级名>.json  # 分批输入（喂给撰写代理或人工撰写）
    ...
    output_*.json          # 分批增强结果（basis_enh/method_enh/matlist_enh/why）
```

**每一步都必须看脚本打印的校验行**。任一 `FAIL` 先修数据再往下走，不要带着脏数据生成交付物。

## 四、撰写工作流（关键步骤）

### Step 1 抽取与结构校验

跑 `extract_source.py`，必须确认：

- `items` 数量与人工目视的总行数一致；
- `sum(score)` 等于指标总分（如 100 分）——**分值优先从考查要点文本的"（X分）"解析**，指标表里的分值列常常只填了一部分，不可依赖；
- `no code rows` 为空、`dup codes` 为空；
- `score mismatch` 为空（文本分值与分值列交叉核对）。

### Step 2 档位、负责人、文件夹映射

跑 `tier.py`：

- **档位规则**：见 `references/tier-rules.md`（分值 ≥1.0 → 详；主观且 ≥0.3 → 详；≥0.3 → 标准；其余客观 → 简）；
- **负责人映射**：默认按二级指标段映射职能角色，见 `references/owner-map.md`；机构人少时可合并角色（用 `--owner-map` 传入自定义映射）；
- **待核验标记**：源依据中不含 `第X条 / 令第X号 / 〔年份〕` 的项，标 `needs_verify=true`（**不因此升档**，升档会让"详"泛滥）；
- **编号笔误检测**：末级编号前 3 段与三级编号不一致的标 `code_mismatch=true`，在交付物中显式注明，不要静默改号。

### Step 3 分批撰写四项内容

**批量策略**：按一级指标切分为 5 个批次（`分块` 而非逐项），每批交给一个撰写回合/子代理，避免上下文溢出。批次提示词模板见 `references/batch-prompt-template.md`——**直接复用，不要临场重写**，模板里已经固化了"禁虚构条款号""[实操指引]标注""年度口径""文件级命名"等硬约束。

四项内容的分工与撰写要点：

| 字段 | 写法 |
|---|---|
| `basis_enh` | 以源 `basis` 为基础，从同行 `lawtext` 中提取条款号/文号补齐；无正式文号的保留原名 + 追加 `[实操指引，非法定依据]`；**全部项须核对现行版本与文号，不得凭记忆写条款号**（核验动作见 §八） |
| `method_enh` | 60–120 字，按类型分化：客观＝备查材料＋核验要点；主观/客观+主观＝补现场询问、案例讲解、执行痕迹核查 |
| `matlist_enh` | 从源 `matlist` 细化为文件级：`1. 2. 3.` 编号、逐条一行、建议文件名、年度范围、格式（PDF/Word/Excel/PNG/JPG） |
| `why` | 按档位定简繁：详＝2–4 句（依据→专家怎么用→注意什么）；标准＝1–2 句（缺了扣哪项）；简＝半句–1 句 |

### Step 4 合并前校验（必做）

对全部批次输出做一致性检查：

1. **覆盖率**：批次 code 集合 == 源 code 集合，无缺失、无重复；
2. **字段非空**：四个增强字段均非空；
3. **口径统一**：同一法规的令号/文号在全批次中**只有一个版本**（典型高风险项：信息公开办法、年度支出与费用规定、慈善法条号——口径以发布机关官网为准）；
4. **依据完整性**：`basis_enh` 100% 含正式文件名称（`《》`）；纯评估导向性要求也要挂上指标文件本身作为锚点。

校验脚本可用 `scripts/check_batches.py`。

## 五、交付前自检清单

- [ ] 末级项数 = 源表末级行数；分值求和 = 总分
- [ ] 每个 `code` 都有且只有一条记录
- [ ] `basis_enh` 全部含 `《》`；无法定依据的已标【实操指引，非法定依据】
- [ ] 同一法规文号全局唯一（无 61 号令/81 号令混用这类冲突）
- [ ] `matlist_enh` 每条都有年度范围与格式
- [ ] `why` 简繁分布与档位分布一致（详/标准/简 不应全挤在一档）
- [ ] `code_mismatch` 项已在交付物备注中注明
- [ ] `needs_verify` 项已列出清单交用户复核

## 六、环境与依赖

- 依赖 `openpyxl`。若环境无该包，脚本会尝试从 WorkBuddy 隔离目录导入；仍失败则按提示安装到隔离环境（**不要**全局安装）：
  `python -m pip install openpyxl -q --target "<WorkBuddy python tmp_pkgs 目录>"`
- 运行 Python 时使用环境提供的托管解释器路径；不要 `pip install -g`。

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 分值列大量为空、求和远低于总分 | 分值只填在考查要点文本里 | 从文本"（X分）"解析（脚本已内置） |
| 只读到 7 列，缺规定依据/法规原文列 | **只读模式（read_only）会漏读部分列** | 用普通模式加载工作簿；这是高频踩坑点 |
| 编号重复或与三级指标不匹配 | 源表笔误 | 标 `code_mismatch`，交付物备注说明，不静默改号 |
| 档位"详"占比过高 | 把"依据缺条款号"当升档理由 | 缺条款号只标 `needs_verify`，不升档 |
| 一级指标名称不一致（"党建"vs"党的建设"） | 不同版本/不同人填写 | 以指标表原文为准，全局统一 |

## 八、法规口径核验（内联规则）

**每次任务启动都要重新核验，不得复用上一次任务的版本结论**——法规会更新，指标会换版。

### 核验什么

从清单底表中提取全部被引用的法规/文件，去重后逐条记录三件事：
**现行有效版本 / 是否被替代（被谁替代、何时生效）/ 施行日期**。

| 类别 | 例 | 核验重点 |
|---|---|---|
| 法律 | 慈善法（含修正情况） | 是否修正过、条号是否变动 |
| 行政法规 | 基金会管理条例 | 是否修订 |
| 部门规章 | 信息公开办法、公开募捐管理办法、社会组织评估管理办法、保值增值投资管理暂行办法 | **令号 + 施行日期 + 是否被新令替代** |
| 规范性文件 | 年度支出与费用管理规定、党建相关文件 | **文号 + 是否被新文号替代** |
| 地方文件 | 省市民政部门评估通知 | 时效性、是否仍在执行 |
| 指导性文件 | 各类"指引""工作方案" | 标注【实操指引，非法定依据】 |

### 信源优先级（从高到低）

1. 法规原文检索源——用于确认名称、条号、文号；
2. **发布机关官网**（.gov.cn / 部门官网）——权威性最高，用于确认施行与废止；
3. 央媒/省媒自有域名——用于印证；
4. 其他——仅作线索，**不作为结论依据**。

> **不接受**：聚合类快讯页、无认证的自媒体转载、来源不明的"法规汇编"网页、AI 生成的法条。
> **微信公众号不作为法规依据来源。**

### 三条铁律

1. **不虚构**——条款号、文号、生效日期、替代关系，一律以核验结果为准；拿不准就标【待核验】；
2. **唯一口径**——同一法规在同一批交付物中只能有一个版本表述，跨批次冲突必须清零后才可交付；
3. **回填并检测**——核验结果回填 `basis_enh`，再用 `scripts/check_batches.py` 做跨批次口径冲突检测。

### 交付后的衔接

本技能的产出（`enriched_meta.json` + 批次输出）是**逐项资料清单的数据底座**，可直接用于：
生成分发版工作簿与归档文件夹树、按清单做打分预演、按缺项生成补料台账。
