# 慈善组织受益对象管理

项目执行阶段最容易被追问、也最容易**事后补不出来**的一块。本技能解决三件事：**名册怎么建、资格怎么审、偏离了怎么办**。

## 什么时候会用到它

| 时机 | 你要做的事 |
|---|---|
| 项目启动、要定名单 | 用第 1 节定名册字段，用第 2 节定筛选与准入口径 |
| 名单已定、要交出去之前 | 用第 6 节三问自检；把名单交给 `scripts/check_roster.py` 跑一遍，拿缺陷清单 |
| 发放或服务当天 | 用第 3 节把签收留痕做实（当天不落，事后补不出来） |
| 审计、检查、评估前 | 用第 4、5 节核偏离情形与变更审批是否齐 |
| 项目中途有人退出／替换 | 用第 5 节做变更记录与审批 |

一句话：**受益对象必须可追溯**——每个受助人都要能回答"给了谁、给了多少、用在哪"。

## 一、名册字段规范

名册不是越全越好，是**最小必要**。按用途分三类字段：

| 类别 | 字段 | 说明 |
|---|---|---|
| **追溯必备** | 姓名（或可对应到具体人的标识）、发放去向、发放方式 | 缺了就无法说明资金物资去向 |
| **资格依据** | 资格类别、认定依据、纳入标准 | 说明"为什么是他"，对应筛选标准 |
| **联系与保护** | 联系电话、必要地址（精确到乡镇／社区即可） | 按最小必要采集；**涉未成年人从严**，另需监护人同意 |

**不要采集**：与项目无关的证件全号、银行账号全号、家庭成员明细、健康档案等。要采集的，写明用途与保管方式。

> 涉未成年人的项目，另见 `references/判定规则索引.md` 的「从严场景」清单。

## 二、资格审核（准入三查）

1. **查资格**——是否符合立项时书面确定的筛选标准（标准要事先定、书面留档，不能边做边定）。
2. **查条件**——是否同时满足资助／服务标准的全部条件（年龄、区域、家庭状况等）。
3. **查重复**——是否在同项目内重复纳入，或与其他项目重复受助。

三查都要留痕，留痕形式可以是审核表、评审记录或会议纪要。

## 三、签收与可追溯

| 给付形态 | 留痕要件 |
|---|---|
| 现金资助 | 名册 + 发放标准 + 签收单**或**银行发放流水（二选一，能对应到人） |
| 实物物资 | 签收单（品名、数量、日期、签收人），与物资台账可对应 |
| 培训／服务 | 参训签到、课时与内容记录 |
| 人员劳务 | 工作量记录、报酬标准、发放签收 |
| 无形给付（账号、使用权、授权等） | 明确内容、期限、范围；开通与使用记录；计价依据 |

发放或服务**当天**留痕，是这一节的全部要点。

## 四、偏离识别（四类，最容易出事的一块）

> 偏离本身就是合规问题。判断标准不是"有没有偏离"，而是**偏离之后能不能说清"为什么、批没批、影响多大"**。

| # | 类型 | 表现 |
|---|---|---|
| 1 | **人群偏离** | 立项写"帮助乡村女孩"，实际受益人以男孩为主 |
| 2 | **代位占用** | 立项写"帮助老人"，钱物主要由其子女或孙辈获得 |
| 3 | **区域／标准偏离** | 执行中擅自放宽或收紧资助区域、资格标准 |
| 4 | **变更未审批** | 有人退出、替换，但无原因记录、无审批 |

`scripts/check_roster.py` 会按名册的性别／年龄／区域分布，对照立项目标人群，给出第 1、3 类的**提示**（提示不是结论，需人工确认）。

## 五、偏离处置

| 偏离性质 | 处置 |
|---|---|
| **客观原因**（对象自然流失、条件变化） | 书面记录原因 + 履行变更审批 |
| **执行失控**（标准被执行者私自放宽） | 在中期报告与结项报告中**如实反映**，不得隐瞒、不得用选择性数据掩盖 |

变更审批要落在项目变更单上，与手册第 2.7 节「项目变更（必须书面）」衔接。

## 六、交付前自检（三问）

1. **给了谁**——每个受助人都能指到名册上的一行？
2. **给了多少**——发放数额／数量能对上标准，且总额不超过预算？
3. **用在哪**——现金有流水、实物有签收、服务有签到，三样能各自对应？

三问里任何一问答不上，就是材料缺口，回去补。

## 七、脚本：名单体检

```
python scripts/check_roster.py --input sample_data/sample_input.json --out ./体检报告.xlsx
```

- **输入**：一份 JSON（结构见 `sample_data/sample_input.json`，字段即填表说明）。
- **输出**：Excel 四表——汇总 / 缺陷清单 / 偏离提示 / 待补材料。
- **规则**：八条，逐条见 `references/判定规则索引.md`。

### 边界与降级（必读）

| 情况 | 怎么处理 |
|---|---|
| 未安装 openpyxl | 自动降级输出 CSV（同目录、后缀 `.csv`），内容一致 |
| 名册缺关键字段（如无性别、无区域） | 相关偏离规则**报"无法判定"**，不猜、不填默认值 |
| 名册量特别大（数千条以上） | 脚本仍可跑，但偏离提示只给分布统计，改由人工抽样 |
| 名单含真实个人信息 | **对外提交前必须脱敏**；脚本输出默认只写"姓 + 人数统计"，不打印完整身份信息 |
| 规则命中 | 命中的是**待核项**，不是违规结论；须人工确认后才写入报告 |

## 八、配套

- **方法依据**：《公益项目全流程合规手册》第 2.2 节（受益对象管理）、2.3 节（给付形态）、3.3 节（归档清单·受益对象类）。
- **空白表格**：`gongyi-project-templates` 技能内的「受益对象审核表.xlsx」「留痕归档清单.docx」。
- **本技能只解决"怎么判"**，不重复"填什么表"。

## 九、免责

本技能为操作性工具，不构成法律意见。依据条文以现行有效版本为准；涉及具体情形的定性，应结合机构章程、资助协议与属地要求复核。
