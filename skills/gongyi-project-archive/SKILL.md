# 慈善组织项目档案归集

项目做完，材料散在各人手上，检查、审计、评估一来就得手忙脚乱。本技能把"一项目一卷"做实：**按八类归集、标清必要与否、缺什么一目了然、卷内目录一键生成**。

## 什么时候会用到它

| 时机 | 你要做的事 |
|---|---|
| 项目进行中 | 用第 2 节清单**随手对**，缺的当期补齐（别等结项） |
| 结项前 | 用第 3 节跑一遍，拿缺失清单；用第 5 节编卷内目录 |
| 迎检、迎审、迎评前 | 用第 4 节的补件顺序，按调取习惯把材料排好 |
| 移交档案室 | 用第 5 节的卷内目录作交接清单 |

一句话：**一项目一卷，八类分册，按卷调取**。

## 一、八类的由来

按《公益项目全流程合规手册》第 3.3 节的分类：**立项 / 协议 / 资金 / 受益对象 / 物资 / 过程 / 成效 / 结项**，共 35 项。

**必要性分两级**：

| 级别 | 含义 | 缺了会怎样 |
|---|---|---|
| **必要** | 无此项即构成材料缺失 | 检查、审计时被认定为材料不全 |
| **尽量有** | 有则举证更充分 | 一般不单独认定为缺失，但影响说服力 |

## 二、八类 35 项清单

| 类 | 项数 | 内容 |
|---|---|---|
| 一 立项类 | 6 | 立项书、立项审批／决议、宗旨与业务范围比对表、资助与实施标准论证记录、关联方识别与交易审议公开记录、重大事项报备回执 |
| 二 协议类 | 5 | 接收侧捐赠／资助协议、转赠侧协议、采购／服务合同、合作方协议、用人／劳务协议 |
| 三 资金类 | 5 | 拨付申请与审批单、银行流水／付款凭证、票据、全口径预算表与预算实际对比表、决算表 |
| 四 受益对象类 | 4 | 资助标准与筛选条件、受益对象名册、签收单／发放流水、变更或偏离说明与审批 |
| 五 物资类 | 4 | 采购比价记录、入库单、出库发放单与签收单、剩余物资处置审批与记录 |
| 六 过程类 | 4 | 进度台账、中期／阶段／年度汇报表、变更审批单、合作方定期对账记录 |
| 七 成效类 | 4 | 成效数据（含前后对比）、受益对象反馈／回访记录、影像记录（含授权）、第三方评估或媒体报道 |
| 八 结项类 | 3 | 结项报告、验收单／验收结论（含签署）、档案归集目录 |

逐项的要求与依据见 `references/八类清单与依据.md`。

## 三、缺失项判定（不是"有没有纸"，是"能不能举证"）

| 情形 | 判定 |
|---|---|
| 必要项未收 | **缺失**，须补 |
| 必要项收了但要素不全（如签收单无签字） | **等于缺**，须补正 |
| 尽量有项未收 | 不认定缺失，标注"建议补" |
| 同类多份材料合成一件（如诸份协议合订） | 不算缺，但卷内目录要逐份列出 |
| 有材料但无归档形态（散在个人电脑） | 归集角度仍算"未归"，先归收到卷再算齐 |

判定口诀：**必要看是否齐、尽量看是否加分、要素不全等于缺。**

## 四、补件顺序（按被调取的习惯排）

检查、审计、评估的调取顺序通常是：**先看资金与受益人，再看程序与过程，最后看成效**。补件按这个顺序排，最省事：

1. 资金类（三、五项）——被最先问
2. 受益对象类（四项）——与资金互相印证
3. 物资类（五项）——与资金、受益人三向印证
4. 立项与协议类（一、二项）——程序合法性
5. 过程类（六项）——过程控制
6. 成效类（七项）——目标达成
7. 结项类（八项）——收口

## 五、脚本：归档体检 + 卷内目录

```
python scripts/check_archive.py --input sample_data/sample_input.json --out ./归档体检报告.xlsx --docx ./卷内目录.docx
```

- **输入**：一份 JSON（结构见 `sample_data/sample_input.json`），列出**已收材料**即可，支持按名称或编号填写。
- **输出**：Excel 四表（汇总 / 缺失清单 / 归集目录 / 补件顺序）；`--docx` 另出 Word 卷内目录。
- **规则**：五条，逐条见 `references/判定规则索引.md`。
- **样例**：`sample_data/sample_input.json`（输入样例，兼填表说明）、`sample_report.xlsx`（归档体检报告样例）、`sample_index.html`（卷内目录样例）。

### 边界与降级（必读）

| 情况 | 怎么处理 |
|---|---|
| 未安装 openpyxl | Excel 自动降级为 CSV（按表分文件） |
| 未安装 python-docx | 跳过 Word 卷内目录，改出 HTML 版卷内目录 |
| 输入的名称与清单不完全一致 | 脚本按**别名表**模糊匹配；匹配不上的列入"未识别项"，由人工确认，不静默丢弃 |
| 项目有特殊材料（如资助方另有要求） | 在 `extra_items` 中补充，不改变八类主结构 |
| 材料已收但要素不全 | 脚本无法判断要素完整性，**须人工按第三节判据复核**（脚本只报"是否归集"，不报"是否合格"） |

## 六、配套

- **方法依据**：《公益项目全流程合规手册》第 3.3 节（归档资料清单·八类）、3.2 节（结项报告）、3.4 节（剩余资金物资）。
- **上游技能**：`gongyi-beneficiary-registry`（受益对象类材料）、`gongyi-material-ledger`（物资类材料）。
- **空白表格**：`gongyi-project-templates` 内的「留痕归档清单.docx」。

## 七、免责

本技能为操作性工具，不构成法律意见。归档范围与保管期限应结合机构档案管理制度与属地要求确定。
