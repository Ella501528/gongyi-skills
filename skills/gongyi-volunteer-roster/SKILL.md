# 慈善组织志愿者名册与服务记录证明

志愿者管理里最容易被追问、也最容易做错的一件事，是**记录**。追问的落点只有一个：**这个人，在什么时间、做了什么、多少小时、谁证明的**。本技能把这件事做成三件能自证的事：**登记实名、记录完整、证明可信**。

## 什么时候会用到它

| 时机 | 你要做的事 |
|---|---|
| 志愿者入册 | 用第一节收全实名基本信息 |
| 每次服务结束 | 用第二节记录服务情况，**10 个工作日内**录完 |
| 志愿者要证明 | 用第三节按要素出具，加盖公章、编号可查 |
| 年度检查、评估、抽查前 | 把名册与记录交给 `scripts/check_roster.py` 跑一遍，拿超期与待补清单 |
| 对外提供名册时 | 用第四节先脱敏，防信息泄露 |

## 一、实名登记：收什么

依据《志愿服务记录与证明出具办法（试行）》（民政部令第 67 号）第五条，志愿者个人基本信息包括：

| 字段 | 说明 |
|---|---|
| 姓名、性别、出生日期 | 与身份证件一致 |
| 身份证件类型与号码 | **实名登记的核心**，须真实、准确、完整 |
| 居住区域、联系方式 | 便于通知与应急联系 |
| 专业技能、服务类别 | 决定岗位适配（见「招募培训与岗位适配」技能） |

两条硬要求：

1. **个人信息可由志愿者本人录入，也可经其同意后由组织录入**（第六条第）。组织发现信息有明显错误、缺漏或与实际不一致的，**应当要求志愿者修改、补充**——不能将错就错。
2. 记录内容不止基本信息，还包括**志愿服务情况、培训情况、表彰奖励情况、评价情况**（第四条）。名册只有姓名电话、没有服务与培训记录，等于没记。

## 二、服务记录：七要素 + 及时性

依据第七条第，志愿者的志愿服务情况包含**七要素**：

**活动名称、日期、地点、服务内容、服务时间、活动组织单位、活动负责人**

- **服务时间以小时为计量单位**，指实际付出的时间；组织应根据活动实际情况**科学合理确定**，不得虚记。
- **及时性**：志愿服务情况与评价情况，应当在**活动结束后 10 个工作日内**完成记录（民政部对《办法》的适用说明）。
- **录入渠道**：可通过民政部指定的志愿服务信息系统记录，也可先以其他系统或纸质载体记录，但**应按统一的数据标准录入民政部指定的信息系统**，实现数据互联互通（第四条第）。
- 志愿者发现本人记录有错误、缺漏的，可以提出；组织**应当及时核实，确有错误、缺漏的予以修改、补充**。

## 三、志愿服务记录证明：六项要素 + 三条规矩

**四条原则**：真实、准确、完整、无偿、及时（第三条第）。

**出具主体**（四部门《关于规范志愿服务记录证明工作的指导意见》）须同时满足：
1. 依法设立的组织或单位；
2. 需要出具证明的志愿者**参加了该单位组织的**志愿服务活动；
3. 客观真实地记录了该志愿者参加志愿服务活动的相关信息。

**证明应载明的六类信息**：

| 类别 | 内容 |
|---|---|
| 志愿者身份信息 | 姓名、证件类型与号码、志愿者编号 |
| 志愿服务信息 | 服务时间（**以小时为计量单位**）、服务内容 |
| 出具主体信息 | 出具主体名称、负责人、经办人、联系方式 |
| 其他 | 证明编号、出具日期及其他需要说明的事项 |

**三条规矩**：
1. **谁记录谁证明**——证明必须由招募志愿者参与慈善服务的组织开具，以记录信息为依据，**无偿、如实**出具。
2. **加盖出具主体公章**；格式参照民政部门提供的规范样式；可通过信息系统查验。
3. **任何单位和个人不得伪造、变造或使用虚假证明**。不依法出具证明的，民政部门可予警告、责令限期改正；逾期不改正的责令限期停止活动（《志愿服务条例》第三十八条）。

> 记录与证明是**抽查**对象：民政部门建立抽查制度，重点检查真实性、合法性，抽查结果向社会公开。

## 四、志愿者信息保护

- 未经志愿者本人同意，**不得公开或泄露**其有关信息（《志愿服务条例》第二十条第）。
- 名册对外提供（如报主管单位、用于公示、交第三方评估）前应做**最小必要**处理：非必要不留证件号全码、不留联系方式。
- 内部流转的名册同样应限权限；本技能脚本在报告中**对人名打码**，即为此故。

## 五、脚本用法

```bash
python scripts/check_roster.py --input sample_data/sample_input.json --out ./名册体检报告.xlsx
```

- **输入**：一份 JSON，结构见 `sample_data/sample_input.json`，字段即填表说明。
- **输出**：Excel 四表——**汇总 / 服务记录明细 / 异常清单 / 待补材料**；未安装 openpyxl 时自动降级为 CSV（同目录，按表分文件，内容一致）。
- **提示**：记录超期阈值默认按 **10 个工作日**折算，可用 `--lag-days` 调整；服务时长上限 `--max-hours` 默认 24。

## 六、判定口径（八条）

规则编号与 `references/判定规则索引.md` 一一对应。

| 编号 | 判什么 | 严重度 |
|---|---|---|
| V1 | 实名基本信息缺失（姓名／证件号／联系方式等） | 高 |
| V2 | 服务记录七要素不全 | 中 |
| V3 | 记录超期（服务结束后超过阈值工作日未记录） | 中 |
| V4 | 服务时长异常（缺、为 0、负、或单次超上限） | 中 |
| V5 | 未录入民政部指定的志愿服务信息系统 | 低 |
| V6 | 应出具证明而未出具，或已出具但要素不全 | 中 |
| V7 | 证明无编号或未加盖公章 | 高 |
| V8 | 名册含未脱敏的个人信息、拟对外提供 | 高 |

## 七、边界与降级（必读）

1. **命中项是待核项，不是违规结论**。脚本输出的是"需要人工确认的点"，须核实后再写入正式报告或对外文件。
2. **含真实个人信息时**：脚本只读输入、不联网；报告对人名打码。**正式提交的原始名册不要用本技能的样例文件**。
3. **没有统一信息系统账号时**：不影响使用。可先用纸质或其他系统记录，**按统一数据标准录入指定系统**是后续动作，不是前提。
4. **缺关键字段时不猜**：如无服务日期，V3 报"无法判定"，不默认按时记录。
5. **数据量大时**：脚本为单机顺序处理，万条级以内无压力；更大规模建议先分年度。
6. **本技能不判定"该不该给这个人出证明"**——那是招募与关系管理的范畴；本技能只判"记录与证明本身是否规范"。

## 八、什么时候不该用本技能

- 需要判定**岗位是否适配、要不要培训**——用「慈善组织志愿者招募培训与岗位适配」。
- 需要判定**哪类活动必须投保、出险怎么处理**——用「慈善组织志愿者风险与保险」。
- 合作方（供应商、服务提供方、联合宣传方）的管理——属合作方主题，不在本技能。
