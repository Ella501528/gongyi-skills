# 慈善组织志愿者风险与保险

志愿者出事，机构最怕两句话："**这个活动本来该买保险的**"和"**买了，但保额不够/没买在点上**"。本技能管的就是这两句话——**该不该买、什么时候买、买多少、出事怎么办**。

> 先纠正一个误解：本技能**不是保险选购工具**。它是**投保义务的判定与留痕**工具：判"哪类活动必须先买"，核"买了没有、买在什么时点、够不够、名单全不全"，并给出"出事后的处置清单"。

## 什么时候会用到它

| 时机 | 你要做的事 |
|---|---|
| 活动立项、招募前 | 用第一节给活动定风险级别，判"是否属可能发生人身危险" |
| 排班、发车/出发前 | 用第二至四节核投保：**有没有、什么时点买、保额够不够、名单全不全** |
| 大型公益活动筹备时 | 用第五节确认主办方投保责任 |
| 出险之后 | 用第六节按处置清单走：救助 → 记录 → 索赔 |
| 年度检查、评估前 | 把投保与出险记录交给 `scripts/check_safety.py` 跑一遍 |

## 一、先分级：哪些活动"可能发生人身危险"

**法定要求**（《慈善法》第六十八条、《志愿服务条例》第十七条）：安排志愿者参与**可能发生人身危险**的志愿服务**前**，应当为其购买**相应的人身意外伤害保险**。

这是**强制义务**（"应当"），不是可选项。判断"是否可能发生人身危险"看活动实质，不看名称好不好听：

| 级别 | 典型情形 |
|---|---|
| **高** | 山地/水域/高空作业、夜间长途、救援、大型群众性活动保障、涉及器械与车辆、接触传染病风险环境 |
| **中** | 户外集体活动、交通往返、有一定体力要求的服务 |
| **低** | 室内陪伴、物资分装、文案与后勤 |

**定为中高，或拿不准，一律按"可能发生人身危险"处理——先投保。**

## 二、投保时点：必须是"安排前"

**硬要求**：投保须在**服务开始之前**完成。活动当天、活动结束后补买，**不算履行义务**。

脚本核对口径：保单生效日（`insured_on`）应**不晚于**活动开始日（`start_date`）。

## 三、保额与险种：要与活动风险"相应"

- "相应"意味着**保额与风险匹配**：高风险活动保额应高于低风险活动；机构可设**最低保额标准**（如 10 万元），脚本用 `--min-coverage` 核对。
- 险种应为**人身意外伤害保险**；如需，可附加意外医疗。**不要用"意外险"泛指一切——要能覆盖该活动的具体风险**。
- 建议做法：与保险公司约定**按次投保**或**年度团体投保**，并明确**新增人员的加入方式**。

## 四、名单与凭证：投了要能证明

- **名单要全**：当天实际参加的人，应都在保单名单内。**"漏了一个人"是最常见的漏洞**。
- **凭证要留**：保单号、承保公司、保额、生效日、被保险人名单，应留档。
- **不得由志愿者自担**：投保费用属组织义务，**不应要求志愿者自行承担**（志愿者可自愿自费加保，但组织义务部分不可转嫁）。

## 五、大型公益活动：主办方的投保责任

**法定要求**（《志愿服务条例》第三十三条第二类情形）：**大型社会公益活动的举办者**，应当按照与志愿服务组织或者志愿者的约定，**为志愿者购买相应的保险**。

即：这类活动除组织自身的投保义务外，**主办方另有投保责任**，须在协议中写清由谁投保、保额多少。

## 六、出险之后：处置三步

1. **及时救助**——第一时间组织救助，这是组织的义务；
2. **留痕**——事故时间地点、经过、参与人、处置过程，形成书面记录；
3. **索赔与协助**——按保险合同及时理赔；**因第三人原因造成损害的，组织应协助志愿者或其近亲属依法向第三人索赔**。

> 提醒：志愿者身份**不是**机构免责的理由。慈善服务中造成损害的赔偿责任，另见《慈善法》第一百一十九条。

## 七、脚本用法

```bash
python scripts/check_safety.py --input sample_data/sample_input.json --out ./保障体检报告.xlsx
```

- **输入**：一份 JSON，含活动与投保信息（`activities`）、参加人员（`participants`）、出险记录（`incidents`）。
- **输出**：Excel 四表——**汇总 / 保障明细 / 异常清单 / 待补材料**；无 openpyxl 时降级 CSV。
- **参数**：最低保额 `--min-coverage`（默认读输入，未给则报"未设定，无法判定"）。

## 八、判定口径（八条）

| 编号 | 判什么 | 严重度 |
|---|---|---|
| S1 | 可能发生人身危险的活动未投保 | 高 |
| S2 | 投保时点晚于服务开始 | 高 |
| S3 | 保额低于机构最低标准 | 中 |
| S4 | 参加人未在保单名单内 | 高 |
| S5 | 无投保凭证留档 | 中 |
| S6 | 大型公益活动主办方未按约定投保 | 高 |
| S7 | 出险未按流程处置（救助／记录／索赔不齐） | 高 |
| S8 | 要求志愿者自担投保费用 | 中 |

规则编号与 `references/判定规则索引.md` 一一对应。

## 九、边界与降级（必读）

1. **命中项是待核项，不是违规结论**。如"保额不足"以机构标准为准，须先确认标准。
2. **机构未设最低保额标准时**，S3 报"未设定，无法判定"——**不猜一个数**。
3. **含真实个人信息时**：脚本只读输入、不联网；报告对人名打码。
4. **本技能不推荐具体保险公司或产品**，也不替代保险专业人士的核保意见。
5. **本技能不判招募与培训**（用「招募培训与岗位适配」），不判记录与证明（用「名册与服务记录证明」）。

## 十、什么时候不该用本技能

- 志愿者实名登记、服务记录、开证明 → 用「名册与服务记录证明」。
- 岗位适配、培训、签协议 → 用「招募培训与岗位适配」。
- 合作方（供应商、服务提供方）的保险约定 → 属合作方主题。
