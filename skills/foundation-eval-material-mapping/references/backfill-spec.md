# 第 6 步：归位结果回填清单主表

> 目的：把「机器已经放进文件夹的东西」摊到负责人面前，让他一眼看出
> **这个文件夹里现在有什么、对不对、还缺什么**——否则归档树是个黑箱，
> 负责人要么重复准备、要么漏看已有材料。

## 一、为什么必须回填（而不是只给清单）

前五步产出的是**文件夹树 + 缺项清单**，各自解决一半问题：

- 打开文件夹能看见东西，但不知道**是否符合指标口径**；
- 看清单知道要什么，但不知道**哪些已经在了**——于是整份材料重做一遍。

回填三列后，「清单要求」与「文件夹现状」在同一行对齐，这一行才真正可交付到人。
示例实测：末级要点中约 90 项已有存量材料、约 494 个文件已就位；若不回填，负责人无从得知，
极易把 555MB 已归位材料当成"还没开始"。

## 二、三列口径（措辞即交付物，勿随意改写）

| 列 | 列名 | 内容 |
|---|---|---|
| A | 当前文件夹内已有资料（存量已放入） | 文件名（大小）逐行列出；空则写「（暂无——本文件夹尚未放入存量材料）」 |
| B | 存量归位状态 | 见下表四档 |
| C | 尚缺/待处理提示 | 下一步动作 + ⚠ 同名多版本警示 |

### B 列四档

| 状态 | 触发条件 | 措辞 |
|---|---|---|
| 已归位 | `status=已归位` | 「已归位：已放入 N 个文件」 |
| 待人工确认 | `status=待确认` 且有文件 / 无文件 | 「部分归位：已放入 N 个文件；其余存量候选是否采用需人工判断」／「未放入：存量中有候选材料…需人工挑选」 |
| 缺项 | `status=缺项` | 「缺项：现有存量资料中未找到对应材料」 |
| 外部征询 | `status=外部征询` | 「外部征询：属外部评价/第三方出具类，机构侧无需备料」 |

### C 列写法要点

1. **缺项**：写"需新备：<缺口描述>"+ 缺项清单里的补充要点，收敛到一句动作；
2. **过宽要点（候选 > 60）**：必须写明"范围较宽（存量候选 N 个），程序未自动放入，需人工挑选"，
   并指路文件夹内《取材指针.md》——**不得让使用者误以为该要点没有材料**；
3. **已归位**：也要写一句"请逐一核对文件名与清单要求是否一致"+ 年度口径，避免"有文件＝达标"的错觉；
4. **外部征询类若同时有存量文件**：先写"机构侧原则上无需专门备料"，再写"N 个文件可作佐证"——
   两句话都要有，否则状态与内容自相矛盾；
5. **同名多版本**：单独一段以 `⚠` 开头，列出文件名族，提示确认唯一权威版本。

## 三、实现要点（踩过的坑）

| 坑 | 后果 | 处理 |
|---|---|---|
| 用计划清单（`placement_plan.json` 的 `materialize`）而非磁盘实际 | 与终态不符 | **以磁盘扫描为准**；两者应一致，可用来交叉核验（本例末级要点 0 不一致） |
| 结构操作后列宽不跟随 | 原列宽全部错位 | 显式重排：插入点之前保持不变，插入三列用 46/26/46（字符宽），其后整体右移 |
| 数据验证不随插列迁移 | 「是否已备齐」下拉丢失或错位 | 按插列位置手工迁移 `sqref`（本例 P2:P146 → T2:T146） |
| 自动筛选范围不更新 | 新列无法参与筛选 | 更新 `auto_filter.ref`（本例 A1:R146 → A1:U146） |
| 底纹接力断裂 | 新列与左邻列不同色 | 按一级指标分五段重刷底纹（1 EEF4FB / 2 FBF3EE / 3 EFF8F1 / 4 F7F0FA / 5 FBF9E8） |
| 列宽单位混淆 | 列过窄/过宽 | 字符宽与像素换算约为 **px = 字符宽 × 7** |

## 四、写入通道选择（重要教训）

两条通道，优先级如下：

1. **本地 editor_sdk 通道**（`tencent-local-office-edit`）：用户能在预览面板实时看到改动。
   但**该服务可能在批量调用中途停止**——实测在连续第 16 次调用时连接被拒（端口 39099–39102 全部关闭），
   **未 `save_file` 的内存改动全部丢失**，需从头重做。
   → 走这条通道时：**每完成一个逻辑阶段就 `save_file`**，不要把保存留到最后。
2. **直接写盘**（openpyxl）：稳定、可复现、可脚本化，代价是用户看不到"实时"过程。
   → 批量结构操作（插列 + 末级要点行 × 3 列写入 + 样式重排）**首选直接写盘**，并在写前自动备份原文件。
   本次最终采用此路径。

不论走哪条，**写入前先备份**，并把「原文件」与「回填前备份」路径报给用户。

## 五、交付前自检

- [ ] 表内条目数逐项等于归档目录实际文件数（逐项比对，0 不一致）
- [ ] 表内条目合计 = 归档树实体文件合计（本例 494）
- [ ] 新列底纹与左邻列一致；数据行开启自动换行
- [ ] 表头、合计行边框与底纹已补齐
- [ ] 数据验证与自动筛选已迁移到新列位置
- [ ] 「使用说明」sheet 已补一节，写明三列含义与"已放入 ≠ 符合要求"的口径
- [ ] 备份文件已生成并告知路径
