# 就位模式与体积控制

归位是整条流水线里**唯一有实体副作用**的一步。选错模式的代价分别是：`copy` 白占几十 GB；`link` 在共享盘上悄悄变成真复制；`index` 无法直接打包分发。三者没有优劣，只有场景匹配。

## 一、三种模式对照

| | `index` 仅索引（默认） | `link` 硬链接 | `copy` 复制 |
|---|---|---|---|
| 磁盘占用 | 0 | 0（同盘） | = 归档树体积（翻倍） |
| 归档树里是什么 | `取材指针.md` + 原始绝对路径 | 外观是实体文件，实际共享数据块 | 真副本 |
| 能否拷给外部 | **不能**（指针只在原机有效） | 拷走即变实际复制，行为符合预期 | 能 |
| 源文件删除后 | 指针失效 | 数据仍在（链接计数减少） | 不受影响 |
| 跨盘 | 可跨盘 | **同盘才行**，跨盘自动降级为 copy | 可跨盘 |
| 可反悔性 | 极高（删 md 即可） | 高 | 中（删副本即可，源不受影响） |
| 适用 | 摸底、家底不清、37G 级存量 | 同盘内部分发 | 要打包给负责人/对外交付 |

**推荐路径**：先 `index` 摸底 → 定稿后对「确实要交付出去的部分」改 `copy`。理由：摸底阶段的误配率高（见 `match-rules.md`），先零成本试错；等 `待人工确认清单` 判完，再实体化，避免复制一堆错文件。

## 二、载体政策（体积控制的核心）

默认参数（`place_files.py`）：

| 参数 | 默认 | 含义 |
|---|---|---|
| `--max-doc-per-item` | 25 | 每要点最多实体化文档数 |
| `--max-doc-mb` | 150 | 单个文档超过则仅登记（扫描件 PDF 常超） |
| `--max-image-per-item` | 4 | 每要点最多图片数（痕迹类证据只需代表件） |
| `--max-image-mb` | 8 | 单图上限 |
| `--max-video-per-item` | 1 | 每要点最多视频数 |
| `--max-video-mb` | 60 | 单视频上限 |
| `raw`（CR2/ARW/NEF） | **永不实体化** | 硬编码，无参数可开 |
| 未下载完成文件（`.downloading`/`.crdownload`/`.part`） | **永不实体化，且不参与匹配** | 硬编码。残缺文件当证据是硬伤 |
| **过宽要点**（候选 > 60） | **整项不实体化**，仅登记候选 | 见下 §2.1 |

**为什么对媒体这么严**：评估专家现场看的是「有没有痕迹、能不能说清」，不是看 200 张原片。一张能标注时间地点的活动照片，证据价值等于全部原片。而媒体是体积的主要来源——没封顶时，几个项目就能产出几十 GB。

**未实体化的文件不会被丢掉**：全部写进该文件夹的 `取材指针.md`，注明原因（超限/过大/底片），需要时可按原始路径取用，或临时复制单个文件。

## 三、体积预演怎么读

跑 dry-run 后看 `归位体积预演.md`：

| 观察 | 含义 | 动作 |
|---|---|---|
| 实体化体积在数百 MB 量级 | 正常（文档为主） | 可直接 `--execute` |
| 体积 > 5GB | 必有大文档或媒体漏封顶 | 看「分板块体积」定位，调参数重跑 |
| 某一级指标占 80% 以上 | 该板块媒体未封顶，或规则过宽导致误配 | 先调规则，再看体积 |
| 「未实体化原因分布」里「超出每项上限」占比高 | 该要点候选文件多，说明要点定义宽泛 | 检查是否多个要点被同一批文件命中 |
| `raw` 数量大 | 正常，底片本来就不实体化 | 无需处理，但要在交付说明里告知机构原片位置 |

## 四、执行前后的检查

**执行前**
- [ ] 已把体积数字报给用户并获确认（**硬要求**，不得跳过）
- [ ] 目标盘剩余空间 ≥ 体积 × 1.5
- [ ] 归档根目录不在任何扫描源目录内部（脚本会自动拒绝）
- [ ] 模式选择已与用途对齐（要分发就必须 `copy`）

**执行后**
- [ ] `validate_placement.py` 退出码 0
- [ ] 归档树内无 0 字节文件
- [ ] 抽查 2–3 个要点文件夹：材料对口、`取材指针.md` 里的原始路径可打开
- [ ] 抽 1 个媒体密集型要点：确认只有代表件，且能看出时间地点

## 五、重跑纪律

- **永远改中间数据后重跑，不手工改归档树**。手工移动的文件在下次重跑时不会覆盖（脚本不覆盖同名），但会与 `placement_plan.json` 失去对应关系，导致校验失败。
- 重跑 `place_files.py` 前，若上次已 `copy`，建议先删掉上次的实体副本（`取材指针.md` 与 `说明.md` 保留），避免残留旧文件。脚本不自动删除任何已存在文件——这是刻意的。
- 人工复核结论要落盘（回写 `match_report.json` 或自建台账），否则每次重跑都要重判。
