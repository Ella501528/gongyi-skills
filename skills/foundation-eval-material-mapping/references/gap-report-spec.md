# 缺口报告规范（三张清单）

盘点出结果后，机构真正要看的是三张表。规范如下——**字段不能省，因为它们决定这张表能不能直接发到负责人手上**。

## 一、状态定义（不可混用的四档）

| 状态 | 判定 | 含义 | 机构动作 |
|---|---|---|---|
| **已归位** | 有 ≥1 个 `high` 置信度文件 | 存量中已有对口材料 | 抽查即可 |
| **待确认** | 只有 `medium` 文件 | 机器不确定是否对口 | **人工逐行判定**（见 `match-rules.md` §五） |
| **缺项** | 无任何命中 | 存量中确实没有 | 按清单补料 |
| **外部征询** | 由评估方或第三方出具的外部评价类材料（如登记管理机关评价、业务主管单位评价） | 机构侧无需专门备料 | 标注口径，必要时附存量佐证 |

> 四档之和必须等于要点总数。`待确认` 不是「差一点就齐了」，而是「还不知道齐不齐」——汇报时不得把它计入完成度。

## 二、缺项清单.csv

| 列 | 说明 |
|---|---|
| 指标编号 | 末级编号（编制笔误项须沿用原编号并加注） |
| 一级/二级/三级指标 | 层级名称，便于负责人定位 |
| 考查要点 | 指标原文，不得改写 |
| 分值 | 该要点满分 |
| 类型 | 客观 / 主观 / 客观+主观 |
| **材料性质** | 「材料类」还是「**执行痕迹类**」——痕迹类＝光有制度没用，必须有留痕 |
| 建议负责人 | 沿用 `enriched_meta.json` 的 owner |
| 对应文件夹 | 相对归档根的路径，负责人照此放 |
| 缺什么 | 具体缺的是什么（痕迹类会点明缺纪要/签到/照片） |
| 补充要点 | 怎么补、注意什么 |

**排序规则**：按「分值降序」排，让负责人先补高分区。交付时另按「痕迹类高分项」单独点出——这类是机构最普遍的短板，也是现场问询最容易露馅的地方。

**使用纪律**：缺项清单是**补料任务单**，不是诊断报告。每一行都应能直接落到「某人 + 某文件夹 + 补某文件」。

## 三、待人工确认清单.csv

| 列 | 说明 |
|---|---|
| 指标编号 / 考查要点 / 分值 | 定位信息 |
| 候选文件数 | 进入本表（含仅登记）的候选个数 |
| 候选总数 | 匹配阶段命中的原始候选总数；**显著大于候选文件数**说明载体政策已做封顶，或该要点已触发规则过宽 |
| 最高分 | 最高候选得分，用于判断把握程度 |
| 命中来源 | 命中了哪些规则/词面词，**这是人工判断的关键依据** |
| 类别标注 | `规则过宽` / `反向证明类` / `外部征询类` / `痕迹类`，可多选以 `·` 连接；无则 `—` |
| 候选文件（前5） | 文件名 + 置信度 |
| 对应文件夹 | 候选文件已被放进哪个文件夹 |
| 处置建议 | 标准三选一：改判已归位 / 部分保留 / 移出并补料（规则过宽项会给出"人工从原始库挑选"的专门建议） |

> 列顺序与 `scripts/place_files.py` 的 `HEAD_REVIEW` **必须严格一致**。脚本已加列数守卫，表头与数据行不等长时拒绝写出并报错——若日后调整字段，两处要同步改。

**为什么要给「命中来源」**：人工判「这份《会议纪要》到底是理事会纪要还是项目会纪要」时，看的是机器凭什么把它放这儿。不给来源，人工复核会退化成重新翻一遍文件。

## 四、带 markdown 指针的作用

每个有材料的要点文件夹内生成 `取材指针.md`，作用有三：

1. **可追溯**：实体化文件都注明「原件：`<绝对路径>`」，评估现场被追问来源时能立刻定位；
2. **不丢件**：未实体化的媒体、底片、超大文件全部登记，注明原因，需要时按路径取；
3. **可交接**：文件夹拷给负责人或上传共享盘时，指针随文件走，接手人知道哪些是代表件、哪些还在原处。

**指针里的路径是原机绝对路径**——对外交付（给评估机构、给客户）时须移除该节，只保留文件名清单，避免泄露内部目录结构。对外交付时须一并移除指针中的绝对路径。

## 五、汇报口径（给管理层看的三句话）

1. **覆盖率**：`已归位 + 待确认` 占总项数多少（说明家底厚度）；
2. **确认工作量**：`待确认` 有多少项（说明还需多少人工判断）；
3. **补料重点**：`缺项` 中有多少是痕迹类、合计多少分值（说明补料优先方向）。

不要把四档合并成一个「完成度百分比」汇报——那会把「不知道有没有」算成「有」。
