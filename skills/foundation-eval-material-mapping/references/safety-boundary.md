# 安全边界（硬规则）

本技能会触碰用户的**全盘资料**，是全套技能里风险最高的一环。以下规则不可协商、不可被「效率」或「自动化程度」说服而放宽。

## 一、扫描边界

1. **只扫用户显式指定的目录**。用户没说的一律不扫。
2. **绝不自动扩展到盘符根或用户主目录**。即使用户说「扫整个 E 盘」，也先回报预估文件数与体积、并说明会碰到什么，再确认。
3. **绝不扫系统目录**：`C:\Windows`、`Program Files`、`AppData`、`/System`、`/usr`、回收站、系统卷信息。
4. **个人目录视为只读**：桌面、下载、文档、微信/企业微信文件目录。除非用户明确点名某个子目录且目的合理（如「我评估材料放桌面那个文件夹」），否则不纳入扫描。
5. 跳过的系统与缓存目录：`$RECYCLE.BIN`、`System Volume Information`、`__pycache__`、`.git`、`node_modules`、`.idea`、`.vscode`、`.cache`、`.trash`。

## 二、写入边界（归位动作）

6. **源目录全程只读**：不移动、不重命名、不删除、不修改任何源文件。归位只做「新增副本」或「新增链接」。
7. **不覆盖原件**：目标文件夹内同名文件自动加 `_01`、`_02` 后缀，绝不覆盖已有文件（包括已有的 `说明.md`、上一次的 `取材指针.md` 除外——后者按内容等价重写）。
8. **归档根不得位于扫描源目录内部**。`place_files.py` 会主动拒绝这种配置并退出，防止递归复制把磁盘写满。
9. **不删除任何已存在文件**：重跑不会清理上次的副本——这是刻意的，宁可留下可辨认的旧文件，也不做「智能清理」。需要清理时由用户手动执行或明确下指令。
10. **不碰自动化的任何文件**，不碰 `~/.workbuddy` 下的配置与技能目录（扫描时也排除）。

## 三、空间与体量

11. **`copy` 前必须报体积并获确认**。步骤：dry-run → 读 `归位体积预演.md` 的体积数字 → 在对话中明确报出并说明去向 → 用户确认 → 追加 `--execute`。
12. **媒体一律封顶**，`raw` 底片永不实体化（硬编码）。
13. 若预演体积超过目标盘可用空间的 50%，**必须先报风险**再问是否继续。

## 四、隐私与脱敏

14. 扫描索引（`inventory.json`）会含**绝对路径与文件名**——这是本地中间产物，**不得对外交付**。
15. 输出中不得出现：捐赠人姓名与联系方式、受益人可识别信息、员工身份证号/银行卡/薪酬明细、捐赠人与机构的私人往来。
16. 对外交付件（给评估机构、给客户、发共享文档）必须：
    - 移除 `取材指针.md` 中的原始绝对路径节；
    - 移除负责人姓名（保留岗位角色）；
    - 移除内部备注与商谈记录。
17. 发现敏感文件（身份证扫描件、银行回单、体检报告等）时：**不复制、不索引内容**，仅在缺项/待确认清单中以「[敏感件，需人工单独归档]」提示。

## 五、判断优先级

发生冲突时，按此顺序：

```
用户明确指令  >  本文件的硬规则  >  流程效率  >  交付完整度
```

**唯一的例外**：硬规则中标注「不可协商」的（不删源文件、不全盘扫、不碰系统与个人目录、`copy` 前报体积）——即使用户要求放宽，也先解释风险并请用户以书面方式确认具体范围，再执行。

## 六、发现异常时的处置

| 异常 | 处置 |
|---|---|
| 扫描到的文件数远超预期（如 >5 万） | 停下来回报，确认是否需要按子目录缩小范围 |
| 发现明显的其他机构资料混在一起 | **按机构隔离**，不混入本次归档树；单独列出告知用户 |
| 发现疑似敏感个人信息 | 不复制不索引，列入「需人工单独归档」提示 |
| 目标盘剩余空间不足 | 停止执行，报可用空间与需求空间，等用户处理 |
| 出现权限拒绝（PermissionError） | 记录路径、跳过、在报告中列出，不尝试提升权限 |
