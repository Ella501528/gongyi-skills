# 主体归属规则文件规范（entity_rules.json）

> 由 `classify_entity.py` 消费。**没有它就无法做主体区分**——开工前先生成。

## 一、文件结构

```json
{
  "self": {
    "name": "示例公益基金会",
    "aliases": ["示例基金会", "示例", "SFJJ"],
    "tax_id_tail": "8765"
  },
  "affiliates": [
    { "name": "示例社会工作服务中心", "aliases": ["示例社工中心", "社工中心"],
      "relation": "执行机构", "note": "项目落地执行方" },
    { "name": "某某医疗器械有限公司", "aliases": ["某某医疗"],
      "relation": "供应商/疑似关联方", "note": "需穿透核查" }
  ],
  "excluded_path_segments": ["90-关联方资料-仅供风险核查", "_外部资料", "合作方"],
  "joint_keywords": ["联合", "共建", "会同", "共同主办"]
}
```

## 二、字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `self.name` | 是 | 登记证书全称，用于交付物抬头与标注 |
| `self.aliases` | 是 | 全称、简称、公章名、公众号名、域名关键词、统一社会信用代码后四位。**宁可多写，不要漏** |
| `self.tax_id_tail` | 否 | 统一社会信用代码后四位，兜底匹配 |
| `affiliates[].name` | 否 | 关联方全称 |
| `affiliates[].aliases` | 否 | 关联方别名；**不要用过于通用的词**（如"中心""公司"）以免误伤主体文件 |
| `affiliates[].relation` | 否 | 关系类型：执行机构/合作方/供应商/理事单位/受同一控制/疑似关联 |
| `excluded_path_segments` | 否 | 路径中出现即直判 `AFFILIATE`——用于已人工分拣过的外部目录 |
| `joint_keywords` | 否 | 命中即为共有/联合材料线索 |

## 三、生成方式

**不要靠猜**。从以下来源提取别名：

1. 用户口述/上传资料中的机构署名与落款；
2. 扫描目录中出现频率最高的机构名片段；
3. 慈善中国/官网的机构公示名称（公开信息补 `name` 的最可靠来源）；
4. 目录的一级文件夹名（常常就是机构名）。

生成后**必须回读给用户确认**主体清单——尤其是关联方名单。判错一个别名，整批文件的归属就反了。

## 四、输出物

| 文件 | 内容 |
|---|---|
| `work/inventory.json` | 每个文件对象新增 `entity`（`SELF`/`AFFILIATE`/`JOINT`/`UNKNOWN`）与 `entity_hint`（命中线索） |
| `work/affiliate_index.json` | 仅归属 `AFFILIATE`/`JOINT` 的文件索引，附 `所属关联方`、`关系`、`用途限制` |
| `work/entity_summary.json` | 四档统计 + 未指派文件数，用于口径说明 |
| `work/主体归属统计.csv` | 同上，给人看的表格 |
| `work/待指派归属清单.csv` | `UNKNOWN` 文件清单，须由用户指派后才能使用 |

## 五、安全阀

- 脚本**全程只读**，不移动、不复制、不删除任何文件。
- `UNKNOWN` 与 `JOINT` 文件**不进主体归档树**，进人工确认队列。
- 每股一批都要先报数量再动，禁止静默处理。
