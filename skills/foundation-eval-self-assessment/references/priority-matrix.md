# 整改优先级矩阵

## 一、横纵轴定义

- **横轴：分值权重** —— 该条目分值 / 板块总分，或占失分总额的比例。用"能挽回多少分"衡量。
- **纵轴：补救难度** —— 综合"材料获取难度 × 是否需实质调整 × 是否需外部配合 × 时间窗口"打分：

| 难度 | 判据 | 典型项 |
|---|---|---|
| **低** | 内部材料即可补齐，1–2 周内完成 | 补齐会议四件套、补挂公开信息、补签承诺书 |
| **中** | 需跨部门配合或补执行痕迹，1–2 个月 | 补充执行台账、建立关联交易台账、口径重算 |
| **高** | 需实质调整或外部程序，3 个月以上 | 修订章程并备案、换届、支出结构调整、整改报备 |

## 二、四象限动作

| 象限 | 特征 | 动作 | 责任层级 |
|---|---|---|---|
| **① 高权重 × 低难度** | 最容易拿到的高价值分 | **本周内动手**，指定单一责任人 | 执行层 |
| **② 高权重 × 高难度** | 决定等级归属的硬骨头 | **立专项**，明确里程碑与上报节点 | 决策层 |
| **③ 低权重 × 低难度** | 顺手分 | 批量处理，一条流水线做完 | 执行层 |
| **④ 低权重 × 高难度** | 性价比最低 | **建议放弃**，书面记录理由 | 决策层知情 |

## 三、整改台账字段（与 SKILL.md §七 对齐）

| 字段 | 说明 |
|---|---|
| 编号 | 与指标编号一致，可追溯到清单与说明文件 |
| 问题描述 | 一句话说清"缺什么/不符在哪" |
| 失分性质 | 证据缺失型 / 执行不足型 / 实质不符型 |
| 预计可挽回分值 | 数值 |
| 优先级 | ①/②/③/④ |
| 整改动作 | **可验证**的动作，写"补齐2023–2025年理事会签到表并扫描归档"，不写"加强管理" |
| 责任角色 | 职能角色（不写人名，人名在派发时填） |
| 时限 | 具体日期 |
| 证据形式 | 交付物形态（PDF/照片/台账/说明函） |
| 状态 | 未启动 / 进行中 / 已完成 / 已放弃 |
| 复查方式 | 谁在什么时点复核，复核什么 |
| 放弃理由 | 仅④象限填写，须决策层确认 |

## 四、排序输出格式

```
【立即做】①1.4.3 支出结构口径重算   可挽回 2.5 分   2周   财务负责人
【立即做】①4.2.1 信息公开补挂 3 项   可挽回 1.8 分   1周   办公室主任
【立专项】②1.2.3 章程修订备案       可挽回 1.5 分   3个月 秘书长
【顺手做】③1.1.2 场地照片补拍       可挽回 0.2 分   1周   办公室
【建议放弃】④5.4.2 特色品牌活动     可挽回 0.3 分   6个月   决策层确认
────────────────────────────────
合计可挽回：6.3 分 / 需放弃：0.3 分
```

**要点**：每一行都要有"可挽回分值"，让决策层看到投入产出——这比"存在若干问题需要整改"有用一百倍。

## 五、加急模式（≤7 天，含 3 天倒计时）

时间塌缩时，排序规则从"分值权重 × 补救难度"切换为**性价比优先**：

```
性价比 = 可挽回分值 ÷ 所需工时
```

执行口径：

1. **先算性价比再排序**，只保留能在剩余时间内完成的项；
2. 排序输出列改为 `T-N 天 / 小时` 而非"周"，每项必带**责任人与绝对时点**；
3. **只做 ① 象限**（高权重 × 低难度）中 1 天内可闭环的项，其余降为 P1/P2 或明确标记为"本轮放弃"；
4. **必答三问**：哪些分现在还能抢回来、哪些已经不可能、放弃的代价是多少。**不可为的部分必须明说**，不许用"建议持续推进"含糊带过；
5. 加急下**不做**完整指标拆解与归档树建设，只给"投哪里最划算"的排序表 + 最小材料清单。
